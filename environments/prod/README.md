# environments/prod

The production environment: network, cluster, database and everything the apps need in AWS. One stack,
state `s3://terraform-backend-home-work/prod/terraform.tfstate`. Values are set inline (no tfvars): the
folder *is* the environment; a dev environment would be a sibling folder.

Files are grouped **by component**: everything about RDS (instance, security group, alarms) is in `rds.tf`,
and so on.

| File | What |
|---|---|
| `vpc.tf` | VPC `prod-vpc` `10.1.0.0/16`, 3 AZs, public / private / database subnets, NAT per AZ, flow logs |
| `eks.tf` | EKS cluster `hw-eks-prod`, add-ons, system node group, IAM roles for add-ons, EBS snapshots (DLM), the `platform` module |
| `platform/` | Karpenter + Argo CD ([README](platform/README.md)) |
| `rds.tf` | PostgreSQL `hw-rds-prod`, its security group and alarms |
| `backend.tf` | What the backend app has in AWS: JWT secret, IAM role for the database login |
| `frontend.tf` | The public entry point: ALB lookup and its alarms |
| `monitoring.tf` | Loki log bucket, IAM roles for Loki / Grafana / Alertmanager, alert topics, heartbeat alarm |
| `outputs.tf` | Values used elsewhere (mostly by `k8s-envs`) |
| `terraform.tf` | Backend, providers (`aws`, `helm`, `random`) |

## Network (`vpc.tf`)

| Subnets | CIDR (per AZ) | Used by | Internet |
|---|---|---|---|
| public | `/22` | ALB, NAT gateways | in + out |
| private | `/20` | EKS nodes **and pods** (every pod gets a VPC IP) | out via NAT |
| database | `/24` | RDS | **none** (no route to the internet at all) |

- **One NAT gateway per AZ**: an AZ outage doesn't take away egress from the other two. Trade-off: 3x the
  NAT cost; a single NAT is a two-line change.
- Separate database subnets: no internet route even if something inside is compromised, and pods can never
  use up the database's IPs.
- VPC flow logs to CloudWatch (all traffic, 60 s, 30 days).

## Cluster (`eks.tf`)

- EKS **1.36**, private + public API endpoint (public one: see known gaps), Kubernetes secrets encrypted
  with KMS, control plane logs (api, audit, authenticator) to CloudWatch for 30 days.
- **Access**: API authentication mode with access entries; the creator gets no implicit admin. Only the
  IAM user `jovan-admin` is cluster admin (to change for another account or with SSO).
- **System node group** `system`: 4× t3.medium on-demand, labelled `workload-type=system` and tainted
  `CriticalAddonsOnly`, so only cluster add-ons run there (CoreDNS, Karpenter, Argo CD, monitoring, …).
  Apps run on nodes Karpenter creates. AMI release pinned (nodes change only when the pinned version is bumped).
- **VPC CNI prefix delegation** + `maxPods: 110`: the small instance types allowed in this account would
  otherwise fit only 17 pods per node.
- **Add-ons** (EKS-managed): VPC CNI (with network-policy enforcement enabled), kube-proxy, CoreDNS (3
  replicas spread over AZs), EBS CSI driver, metrics-server, Pod Identity agent.
- **IAM for pods** without keys: IRSA roles for the VPC CNI, EBS CSI driver, AWS Load Balancer Controller,
  and one role per namespace for External Secrets (a namespace can read only secrets named `<namespace>/*`).
- **EBS snapshots**: the EBS CSI driver tags every volume it creates with `backup=daily`; a Data Lifecycle
  Manager policy snapshots those daily at 04:00 UTC and keeps 7 (AWS Backup is blocked in this account).

## Database (`rds.tf`)

- PostgreSQL 17 on `db.t4g.micro`, **Multi-AZ**, gp3 20 GB with autoscaling to 100 GB, encrypted.
- **TLS enforced** (`rds.force_ssl`), reachable only from the EKS nodes' security group, slow queries (> 1 s)
  logged to CloudWatch.
- **Credentials**: the master password is generated and rotated by RDS in Secrets Manager (never in
  Terraform state). It's used only by the migration Job. The app logs in as `app_user` with **IAM
  authentication** (a 15-minute token from its pod role, no password).
- **Backups**: automated, 7 days, point-in-time restore; kept even if the instance is deleted; final
  snapshot on delete; deletion protection on. Restore steps: [runbook](../../docs/runbooks/restore-db.md).
- Alarms: CPU > 80%, free storage < 2 GB, freeable memory < 100 MB.

## Apps (`backend.tf`, `frontend.tf`)

- **Backend**: a JWT signing key generated by Terraform and written to Secrets Manager (`prod/backend`)
  as an ephemeral, write-only value, so it never lands in the Terraform state. External Secrets syncs it
  into the cluster. IAM role `hw-eks-backend-prod`: may connect to RDS only as `app_user`.
- **Frontend**: the ALB is created by Kubernetes (Load Balancer Controller from the frontend's Ingress),
  so Terraform only **looks it up** to attach alarms (5xx, unhealthy targets, p95 latency). On a fresh
  setup the lookup finds nothing and the alarms are added by the next apply.

## Monitoring (`monitoring.tf`)

The monitoring stack itself runs in the cluster (deployed from `k8s-envs`); this file has its AWS parts:

- S3 bucket `hw-loki-prod` for logs (30 days, enforced by Loki), IAM roles for Loki (that bucket only),
  Grafana (read-only CloudWatch) and Alertmanager (publish alerts).
- **Alerting**: SNS topic `hw-alerts-prod` → email. CloudWatch alarms (RDS, ALB) and Alertmanager both
  publish there. **Dead man's switch**: Alertmanager sends an always-firing heartbeat every 5 minutes to
  `hw-watchdog-prod`; if it stops for 15 minutes, a CloudWatch alarm emails that monitoring is down.
- The email subscription is added by hand, not in code (no personal address in a public repo).

## Apply

```bash
cd environments/prod
terraform init
terraform plan
terraform apply
```

- Needs [`management`](../../management/README.md) applied first (state bucket, ECR, Spot role).
- First apply on an empty account: VPC → EKS → RDS → `platform` (Karpenter, Argo CD) in one run. Argo CD
  then syncs [`k8s-envs`](https://github.com/jelicki-jovan/k8s-envs) and creates everything inside the
  cluster, including the ALB. Run `terraform apply` once more to add the ALB alarms.
- Access to the cluster: `aws eks update-kubeconfig --name hw-eks-prod --region us-east-1`.
- Tearing down needs a specific order (Karpenter's nodes and the ALB aren't in Terraform):
  [teardown runbook](../../docs/runbooks/teardown.md).
